# Windows 历史更新说明

以下整理自项目原有说明，仅保留更新说明，不包含历史源码、旧安装包和本机测试记录。

## 托盘刷新标记修复（v0.14.3）

- Windows 暂时拒绝图标更新时，依次尝试更新／补加／再次更新；如果补加发现旧图标仍存在，也能回到更新操作，避免一次失败后永久只尝试添加而卡住旧图标。单轮最多三次调用，成功后才保存图标缓存，仍失败时由后续事件或定时器继续恢复。不会删除旧图标制造闪烁。
- 刷新反馈使用一个固定的短定时器，普通状态消息不反复重置它。遇到 Windows 回调重入暂时无法访问应用状态时，保留定时器，在下一轮清理标记。快速查询仍至少显示约 0.7 秒，实际查询未结束则继续显示。
- 左键快速重复事件的合并间隔缩短为 250 ms，小于反馈显示时长，消除旧版反馈已消失、下一次点击却仍被一秒防抖忽略的空档。

## 门户短暂同步处理（v0.14.2）

普通状态查询遇到 `wait`，使用同一 HTTP 会话、Cookie 与查询标识，在 250 ms、再 750 ms 后只读复查，最多追加两次，状态接口查询合计不超过 4 秒，并服从已有取消信号和更短的操作期限。明确在线、明确失败或查询异常均立即结束，不追加重试。短暂同步恢复时直接确认在线，保持原会话计时，不再先显示复核提示。

短暂复查后仍为 `wait`，才进入最近在线待复核状态并记录一次；之后明确在线时补一条恢复日志。持续等待或异常仍保留原有后续调度与刷新 HTTP 会话的兜底。认证预检查、凭据只提交一次、下线和明确离线所需的证据规则保持不变。

## 在线后误显示认证中修复（v0.14.1）

普通状态查询收到门户 `wait`，不代表工具又发起了认证。仅在本轮实际提交凭据后的最多 30 秒确认阶段保留橙色；此前已确认在线但后续收到 `wait` 时，显示蓝色“最近已认证在线 · 正在复核”，保留最近会话、运营商和计时起点，当前时长带待确认标记。再次明确在线后恢复绿色；连接身份变化则清除旧会话。

门户持续返回 `wait` 或查询异常后丢弃缓存的 HTTP 查询会话，下一次调度重新建立会话和发现门户，作为可能失效的 Cookie／连接的兜底。保持现有只读复查间隔和退避策略，不因同步中而重复提交密码。运行记录在进入复核时说明原因，同一次等待过程不反复刷日志。

## 性能与边界修复（v0.14.0）

- 日志改用共享分块快照，追加时最多复制当前 128 条尾块，避免复制整份历史文字；今日重连统计按日志事件与北京时间日期缓存。运行状态窗口只在日志、筛选、页码、日期或保留期限变化时重新生成记录，在线时长仍每秒更新。
- 定时电源窗口改为每个窗口一个后台线程，空闲时只检查文件元数据；计划文件变化或手动刷新时读取 JSON。关闭窗口释放线程与数据，已注册的电源计划继续有效。
- 后台命令只有成功进入队列才发布取消信号，并通过短同步屏障避免工作线程提前处理；队列满或已断开不再误取消当前任务。
- 统一电源计划的当前倒计时、后续执行、已提交、已跳过等状态。损坏计划单独显示，正常计划仍可管理；损坏项也可清理其带本应用／当前用户标记的 Windows 任务及文件。
- “仅接通电源执行”的计划在提交前再次读取 Windows 供电状态，电池或未知状态跳过本次；Windows 任务在转电池时停止执行器。此策略用于新版创建的计划；旧版已有计划需取消后重建以更换独立执行器。
- 门户 HTML 响应最多 256 KiB，状态、参数、服务、认证与下线 JSON 响应最多 64 KiB。保留原响应字符集解码；登录结果超过限制时进入只读核对，保持一次凭据提交。DPAPI 解密后的系统缓冲区在释放前清零。

在相同 1 万条、每条 400 字节的内存历史中，保留快照并连续追加 100 条的五次交替测试，中位耗时约 88.6 ms → 0.43 ms。这是日志追加专项结果，不代表整体认证或应用耗时。原始测试记录保留在开发者本地工作区，未收入发布仓库。

## 账号窗口密码回填修复（v0.13.1）

“设置 → 账号与密码”现在从后台当前账号读取密码，在原生 Windows 账号窗口中以掩码回填，同时显示实际的“记住我的密码”状态。本次运行中未勾选记住的密码也可回填，重启后则需重新输入。读取走一次性后台回复，不把密码加入通用状态、日志或剪贴板，也不发起认证。

不修改直接确认时保留原配置，不重置网络任务；取消和空密码错误不保存。密码改动保存失败时保留原账号数据，勾选记住后仍使用 Windows DPAPI 加密保存。长度超出原生窗口容量时拒绝回填，防止静默截断已有密码。

## 定时电源（v0.13.0）

校园网工具 → 定时电源，打开独立配置窗口；关闭窗口后继续在托盘运行。支持关机、重启、睡眠、休眠，以及从睡眠／休眠定时唤醒。完全关机后的定时开机需设备 BIOS/UEFI 提供 RTC / Resume by Alarm，软件不宣称支持从完全关机状态启动。

- 倒计时：2～10080 分钟；指定时间：本地日期与时间，至少提前 90 秒，首次执行可安排在一年以内。
- 指定时间支持一次、每天、工作日（周一至周五，不含法定节假日调休）；倒计时仅一次。窗口展示实际下次执行时间、供电条件和最近执行结果，后台读取本地计划实时更新，保留列表选择。
- 执行前约 60 秒出现独立倒计时窗口，可取消本次；关闭倒计时窗口也会取消。配置窗口的“取消计划”停用本次与后续执行，“移除”进一步删除记录；可以核对 Windows 中的实际任务状态。
- 使用当前用户的 Windows 计划任务与 AppData 下独立执行器，退出 SHUNet、关闭窗口或移动托盘发布文件后，已创建任务仍可运行。需要保持当前用户登录（锁屏可以），默认仅接通电源时执行，可勾选电池供电也执行。
- 不补执行错过的关机、重启、睡眠、休眠；执行器核对有效时间、计划许可和本次执行编号，重复启动不会重复操作。重复电源计划若在未来九天内会于两分钟内碰撞，拒绝新建。最多 20 项待执行计划、保留 100 项记录。
- 关机与重启不强制关闭应用，未保存工作可能阻止操作；休眠不可用时明确提示。设备和电源策略可能禁止唤醒，工具不修改休眠开关、唤醒策略或 BIOS。

计划数据单独保存在 `%APPDATA%\CampusLinkTray\power-plans`，不随账号配置导入／导出。只管理带当前用户和本应用标记的 Windows 任务，取消时先撤销本地执行许可。实际电源状态以 Windows 为准，显示“已提交”不等于已经关机或休眠。

参考：[Windows 唤醒计划](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-waketorun)、[系统电源状态](https://learn.microsoft.com/en-us/windows/win32/power/system-power-states)、[关机命令及强制关闭规则](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown)。

## 菜单主题（v0.12.0）

在“设置 → 菜单主题”选择默认、经典或现代，勾选表示当前选择。默认恢复原来的浅色、灰色信息文字与宽松行距；经典保留 v0.11.3 紧凑的系统菜单样式；现代使用白底、淡蓝信息区、蓝色悬停和勾选、微软雅黑 UI 字体。主题统一应用到主菜单、运行状态与记录及其他各级子菜单，独立工具窗口保持原有样式。

主题保存成功后，下次打开菜单生效，重启后保留。旧配置没有主题字段时自动使用默认；导入、导出也包含主题。切换主题不重新认证、不重置在线时长，不增加网络查询；菜单展开期间固定主题和尺寸，状态与时长继续局部实时刷新。Wi-Fi 列表每次打开时仍按最新状态更新，绘制数据随菜单销毁一并释放。

## 实时菜单稳定性修复（v0.11.3）

修复实时刷新造成的菜单闪动、宽度突然变化和子菜单被打断。菜单打开时确定文字区域尺寸，顶部四行和四个动态动作使用固定行尺寸及系统菜单字体，超长文字省略；计时、查询和“正在处理…”变化只更新行内缓冲，局部失效后绘制，不再每秒修改原生菜单标题、重新排版或强制整张菜单同步重绘。

鼠标指向子菜单入口（包括尚未展开的悬停等待阶段）或任意子菜单仍展开时，父菜单按钮的可用状态、勾选和命令切换暂缓，返回主菜单后再同步最新值；顶部已有状态和时长继续刷新。仅在实际变化时更新原生状态位，绘制前释放内部借用，避免重入刷新时暂时画空。布局和操作方式仍是四行文字、原生子菜单及“查看详细信息…”入口，不增加网络请求。

主菜单顶部恢复原来的四行文字：Wi-Fi、认证状态、网络类型、在线时长；不在这里显示今日重连次数或下次检测倒计时。“运行状态与记录”恢复原生子菜单，直接显示状态详情、今日重连统计及最近六条日志（新记录在上）。子菜单中的“查看详细信息…”打开保留的独立状态窗口，查看三天完整记录、筛选、分页与复制。三天日志保存、重连统计、迎新网址和 ShuWlan-1X 规则不变。

## 状态概览、重连统计和三天日志（v0.11.0）

主菜单顶部显示 Wi-Fi、认证状态、当前网络类型和在线时长的文字摘要。“运行状态与记录”子菜单显示最近日志及今日重连次数，可通过“查看详细信息…”打开独立窗口：连接状态、今日自动重连、检测策略分组展示，详情与日志分开；支持今天 / 昨天 / 前天 / 最近 72 小时、仅自动重连筛选、每页 200 条、复制状态、复制当前筛选全部记录和打开日志目录。窗口每秒读取本机已有状态，不额外访问门户。

“今日自动重连”按北京时间计算：仅统计本次曾确认在线、随后意外下线时实际发出的自动认证请求；首次自动认证、手动认证、已经在线时跳过登录和发送前失败均不计数。门户确认恢复后增加“已确认恢复”，重复查询不重复计数；其余请求显示“未确认”，包括失败和结果未知。统计与日志重启后保留，新版首次使用从零开始，不能追溯旧版仅存在内存的记录。跨午夜按请求发生日期归属。

日志位于 `%APPDATA%\CampusLinkTray\runtime-logs`，按北京时间分日保存为 JSONL；启动及运行中每小时清理超过 72 小时的记录。仅清理本应用命名的日志文件，保留其他文件；写入失败时继续显示内存记录并提示。账号和密码在写入前隐藏，不保存门户参数、Cookie 或会话标识。

ShuWlan-1X（不区分大小写）为特殊 802.1X 校园 Wi-Fi：请在 Windows Wi-Fi 处输入账号密码连接。软件识别为“802.1X 已连接 · 无需网页认证”，不做门户检测、网页认证或网页下线；手动覆盖为校园网模式也不会绕过此排除。菜单连接入口打开 Windows Wi-Fi 设置，不生成企业无线配置或处理企业密码。上海大学迎新系统使用提供的 newsso 单点登录入口；升级和导入会替换旧的默认入口，保留自定义链接及已删除的收藏。

## IP 信息与局域网设备（v0.10.0）

从“校园网工具”打开两个原生窗口，可同时使用，关闭窗口不会退出托盘或执行校园网下线。

- **IP 信息与出口查询**：切换本地活动接口，查看并逐项复制内网 IPv4、本机 IPv6、网关和 DNS；另查询直连和显式代理出口的公网 IP、国家/地区，也可复制全部结果。公网查询按系统路由，与下拉框选择的本地接口独立。默认优先展示有网关的物理接口，VPN 等虚拟接口也可选择。IPv6 链路本地地址附带接口作用域。直接编辑框支持选择文本复制。
- **局域网与共享设备**：只读识别 Windows Internet 连接共享（ICS）下游接口，查询 Windows 热点客户端和接口 ARP/IPv6 邻居表。默认筛选“热点 / USB 共享设备（推荐）”，USB/RNDIS 接口有独立标记；未连接开发板时显示空状态，不把校园 WLAN 的邻居当作开发板。可切换任意活动接口或查看全部接口。显示 IP、MAC、状态、接口、来源和名称，支持复制所选 IP 或当前筛选的全部记录。排除本机、广播、多播、未解析及不可达记录。

“直连”跳过 HTTP/SOCKS 代理，但系统路由或 TUN/VPN 仍可能接管；“代理”显式使用当前系统配置的代理地址（未设置时使用应用保存地址），连接失败单独提示，不回退直连。代理软件可能按自己的规则直出，因此两种公网 IP 相同也可能是正常结果。国家/地区是 IP 归属地，并非设备真实位置。公网查询使用 [ipwho.is HTTPS 接口](https://ipwhois.io/documentation)，只在打开/刷新该窗口时请求，存在服务限额或暂时不可用的情况。一个出口失败不覆盖另一个出口及本地接口结果；查询期间网卡或代理配置变化会使公网结果失效并提示刷新。

设备列表不是完整 DHCP 租约表：热点客户端列表可确认当前连接；邻居缓存仅代表该接口近期见过的地址，缓存状态明确标注“在线待确认”。设备休眠或尚未通信时可能不在邻居表中，不能据此断言未连接。Windows 热点接口受系统版本或权限限制时降级显示缓存，并明确说明来源。手机向电脑 USB 共享上网时，手机才是地址分配方，电脑无法据此列出手机的其他客户端；电脑向设备共享网络时，可选择相应 ICS 下游网卡查看已发现地址。不扫描校园网或整个子网，不更改共享、网卡、路由、DNS 或 DHCP 设置。

两窗口使用各自的按需后台任务，重复刷新合并，关闭取消后续请求；整个进程每类最多一个任务。公共查询单次最多 8 秒，直连/代理分别返回；窗口消息与认证线程独立。闲置时不定期查询公网或设备列表。

接口参考：[Windows 邻居表](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/getipnettable2)、[热点客户端列表](https://learn.microsoft.com/en-us/uwp/api/windows.networking.networkoperators.networkoperatortetheringmanager.gettetheringclients)、[公网归属地接口](https://ipwhois.io/documentation)。

## 当前会话信息（v0.9.3）

右键菜单顶部、托盘悬浮提示和“运行状态与记录”增加网络类型、本次在线时长。网络类型读取当前已确认会话的 `realServiceName` / `service` 等字段，显示校园网、中国电信、中国联通或中国移动；本程序提交认证后若门户缺少此字段，使用该次认证实际选择的运营商。修改设置中的下次认证运营商不改写当前会话。已在线但无法识别运营商时明确显示待确认；尚未认证时标注所选运营商为待认证。普通 Wi-Fi 不按名称猜测运营商。

本程序新认证得到门户接受后记录起点，直到确认在线才显示时长；同一会话的重复状态查询不重置。以单调时钟计时，悬浮提示每秒在本机刷新，不增加门户请求、扫描或线程；右键菜单显示打开时的时长。确认下线、Wi-Fi / 网卡 / IPv4 变化时清零，门户在线会话标识变化时重新计时。查询失败或关闭检测时保留最后确认的时长并标注待确认，重新确认同一会话后恢复计时。

当前校园门户不提供会话登录起始时间。程序启动前就已在线，或登录请求结果未知后才观察到在线时，显示“首检起”，表示从本程序首次确认该会话起计时，不冒充完整历史时长。会话标识仅在内存中比较，不展示、不写入日志。

## 认证流程优化（v0.9.2）

认证预检查取得的当前门户页面、Cookie 和物理 Wi-Fi 客户端只在本次操作中复用，最长 15 秒。SSID、网卡、IPv4、连接事件或设置版本变化会取消旧操作；仅时间过期允许重新发现一次。提交前仍重新只读查询当前会话，已经在线则不发送密码。优先使用本次门户 HTML 中唯一匹配的运营商，缺失或有歧义才查询服务列表；保留 pageInfo 和原 RSA 加密流程，不跨次缓存公钥或门户参数。

区分已在线、请求接受、明确拒绝和结果未知。登录响应丢失或无法解析时转入只读确认，不立即重发密码。提交后约 1 秒开始确认，后续查询结束后分别等待 2、3、5、8 秒，再按 8 秒间隔查询；确认总预算 30 秒，请求超时也受剩余预算约束。确认期间合并重复认证点击，不将短暂未认证或查询异常交给自动登录；预算耗尽后恢复原独立下线确认及重试间隔。定期检测关闭时，也只确认本轮，不改变检测开关。

运行记录增加认证总耗时、HTTP 请求数、密码提交次数及预检查、页面参数、运营商、加密、提交、在线确认分段耗时，不记录账号密码、跳转查询或会话标识。顺带修复下线确认：出现登录页仍需会话接口明确返回未认证，避免网关在已在线时返回登录页造成误判。

同环境原版与优化版的实测和限制见 开发者本地的性能对比记录（未收入发布仓库）。

## 认证引导兼容修复（v0.9.1）

修复在当前校园引导设备上出现的“无法访问认证网关”：已在手机 USB 共享、校园 Wi-Fi 与 VPN TUN 同时启用的环境复现，原请求经过网关跳转到 `123.123.123.123` 时被提前关闭。对照验证发现设备接受传统 `Host:` 请求头，却会关闭小写 `host:` 请求。校园认证客户端现统一使用 HTTP/1.1 和传统请求头大小写，覆盖状态查询、认证、下线及其前置发现流程；继续绕过系统 HTTP 代理并绑定当前物理 Wi-Fi 的 IPv4，不更改 VPN、系统路由或手机共享。

已在该环境中完成校园网认证，并通过门户在线接口独立确认在线，返回 IP 与物理 Wi-Fi 一致。登录接口接受请求与实际在线之间可能有短暂同步延迟，仍以在线接口确认为准。新增 GET / POST 原始请求头回归测试；网关请求失败会区分超时、系统网络错误或提前断开，并记录失败的主机及跳转步数，隐藏查询参数及会话标识。该修复经过当前 TUN 环境验证，不代表能覆盖所有 VPN 的专用拦截策略。

## 运营商选择（v0.9.0）

在 **设置 → 运营商** 中选择 **校园网 / 中国电信 / 中国联通 / 中国移动**，菜单以单选圆点标出当前选择，默认校园网。选择后自动保存，重启、配置导入导出均保留；旧配置缺少 `operator` 时默认校园网。从桌面版重新导入账号时保留托盘版的运营商选择。配置值为 `campus / telecom / unicom / mobile`。

手动认证、自动认证和自动重连均使用所选运营商。程序按门户服务列表或页面中的显示名称匹配实际提交值，校园网在当前门户中为 `shu`，其他三项为对应中文名称；不会改写账号或自行增加后缀，也不会退回门户的默认运营商。门户未提供所选服务时保留选择并提示确认。

切换选择不会主动下线当前在线会话；新选择在下次认证时生效。账号只开通校园网时，选择其他运营商后可能返回“未绑定服务对应的运营商”等权限提示，这是门户的正常认证结果。保留返回原因及当前选择，已识别的未开通或未绑定提示会暂停自动重复提交；更正账号或运营商选择后可恢复。运行状态与记录显示所选运营商。验证覆盖四项参数映射和配置兼容性，不使用用户账号测试未开通运营商的登录。

## 最近修复

v0.8.7 改进左键查询反馈：请求加入后台队列后立即显示刷新标记，悬浮提示区分等待处理和查询中；扫描、认证等任务忙碌时合并排队，不直接忽略查询。网络身份变化时保留手动查询标记并使用当前网络颜色；后台定期查询不覆盖尚在显示的手动反馈。手动查询先发布处理标记，刷新连接后重新绑定当前网络，复位遗留的非活动待查询状态；运行记录补充接收、完成、失败及连接变化的信息。兼容旧版托盘回调的鼠标左键抬起事件，仍通过一秒去重避免重复提交。

v0.8.6 修复 v0.8.5 左键查询时的崩溃：WinRT 的静态接口缓存保留到进程结束，现在同步保留其 MTA 运行环境，避免单次读取结束后销毁环境、下次查询访问失效接口。每线程初始化仍成对释放；进程仅保留一份 MTA 引用，继续使用 GetConnectedSsid。新增连续 100 次实时读取和 10 次新线程读取的本机回归检查。

v0.8.5 将 Wi-Fi 名称读取改为微软推荐的 `WlanConnectionProfileDetails.GetConnectedSsid()`，按网卡 GUID 匹配当前物理 Wi-Fi，不再调用会请求 BSSID 的 `WlanQueryInterface(current_connection)`，读取失败时也不回退到旧接口。校园网未认证、多网卡和 VPN 场景不依赖默认互联网连接。保留 v0.8.4 的名称缓存：定期检测仍核对网卡连接状态和 IP；无线连接变化、睡眠恢复和手动查询使缓存失效，认证、下线前实时核对。正常监听时每 10 分钟重新读取名称，监听不可用时缩短为 60 秒。附近网络扫描行为保持原样，启动及手动刷新扫描仍可能触发 Windows 位置提示。

若原 `SHUNet.exe` 正在运行，更新不会强制关闭或覆盖该文件；可退出后将新版替换为 `SHUNet.exe`。若从不同路径启用新版，请在菜单中更新开机启动项。

工具统一命名为 **SHUNet**，exe 的产品名称、托盘提示、对话框和内置说明使用此名称。为兼容升级，配置仍保存到 `%APPDATA%\CampusLinkTray\settings.json`，原账号、偏好和收藏继续生效；保留旧版单实例标识以避免新旧版本同时守护。

## 五档状态检测与自适应策略（v0.8.1）

在 **设置 → 状态检测** 中切换“启用状态检测”，并从自适应 / 极高 / 高 / 中 / 低中选择一个模式。菜单名称标明秒数，自适应显示 10→30→60 秒。档位全局生效，自动保存到 `detection_level`，重启及配置导入导出时保留。旧配置缺少档位字段时默认使用中档；选择档位本身不打开已关闭的状态检测。

| 模式 | 稳定在线时的查询间隔 | 疑似下线复查间隔 | 查询异常后的退避间隔 |
| --- | --- | --- | --- |
| 自适应 · 10→30→60 秒 | 10 → 30 → 60 秒 | 2 秒 | 3 / 6 / 12 / 30 / 60 / 120 秒 |
| 极高 · 3 秒 | 3 秒 | 2 秒 | 3 / 6 / 12 / 24 / 48 / 60 秒 |
| 高 · 10 秒 | 10 秒 | 2 秒 | 3 / 6 / 12 / 24 / 48 / 60 秒 |
| 中 · 30 秒（默认） | 30 秒 | 3 秒 | 5 / 10 / 20 / 40 / 80 / 120 秒 |
| 低 · 120 秒 | 120 秒 | 5 秒 | 10 / 20 / 40 / 80 / 160 / 300 秒 |

间隔从查询结束后计算，实际完成时间还受请求超时、扫描及其他串行任务影响。四个固定档位与自适应采用同一套门户证据标准，档位改变查询及时性，不降低地址核对和掉线确认要求。极高档遇到异常时仍逐步退避，避免持续失败时每 3 秒重复请求。

自适应刚确认在线时每 10 秒检查；连续 3 次正常后改为 30 秒，连续稳定超过 5 分钟后改为 60 秒。同一网络最近 10 分钟内出现两次明确意外下线时，恢复在线后保持 10 秒检查 5 分钟。超时 / 未知响应和手动下线不计入意外下线次数；切换 SSID 清除该运行会话的稳定统计。仅维护少量时间戳和计数器，不增加线程或无限历史记录。

切换档位保存成功后仅调整调度，不重置首次登录机会、手动暂停、账号错误保护或认证重试冷却。关闭检测后可提前选择档位，重新开启时生效。读取默认配置遇到无效档位时单独恢复为中档并提示；导入文件遇到无效档位时拒绝导入，保留原配置。从桌面版导入账号时保留当前检测档位。

“运行状态与记录”显示所选模式、本轮间隔、下次查询预计等待时间及调度原因，历史在线时间独立展示；菜单内的预计时间以打开菜单时为准。左键单击托盘图标、Ctrl+Shift+S 或菜单中的“立即查询一次”共用一次只读查询，不在该次查询中提交账号密码；已启用的自动策略在后续正常周期继续运行。连续操作在 1 秒内忽略重复，待处理请求合并，不增加线程或堆积任务。查询不重置已确认的证据、稳定统计、账号保护及认证冷却；检测关闭时也可查询一次，不开启定期检测。普通网络只刷新本机连接信息，不访问校园门户。认证等任务忙碌期间查询合并排队；菜单 / 设置窗口打开时不响应图标查询。运行记录可确认手动查询是否已处理及其结果。

网络事件先核对当前 Wi-Fi 的 SSID、网卡索引及 IPv4，忽略未改变校园连接身份的 USB / TUN / IPv6 通知。变化事件合并为有界标记，队列满时仍保留待处理事件。睡眠恢复强制重新发现门户；普通网络与检测关闭时不定期访问校园门户。保留每 60 秒一次的本机连接信息读取，作为网络通知遗漏的后备；该读取不访问门户。

配置示例：

```json
"status_detection": true,
"detection_level": "adaptive"
```

## Wi-Fi 列表修复（v0.7.2）

- 启动先读取 Windows 已有网络列表，再发起一次异步扫描。扫描等待由现有工作线程的短时调度处理，不独占认证 / 设置命令的处理线程，也不新建常驻扫描线程。
- 等待完成通知最多 5 秒；超时、驱动报告失败或部分网卡失败后仍读取可用列表，并保留扫描前的系统缓存。缓存结果明确标注“完整刷新未确认”，不将旧记录冒充完整扫描；全部成功时使用本次返回的列表。
- 扫描记录区分请求返回错误、驱动失败原因码、未收到完成通知和列表访问权限错误。失败不清空原列表，不覆盖校园网认证状态。
- 展开 Wi-Fi 子菜单时读取最新状态，解决托盘主菜单先打开、后台随后完成扫描而子菜单仍使用旧快照的问题；连接操作使用该次子菜单实际显示的网络，避免列表变化后按错下标。
- 即使扫描失败，已知当前连接仍单独显示；菜单保留 Windows Wi-Fi 设置及位置权限设置入口。缓存可能只包含 Windows 已知的部分网络，不保证每次获取全部附近热点。

处理方式参考 Microsoft [WlanScan](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanscan)：扫描为异步请求，允许等待通知或超时后读取网络列表；请求发起时驱动可能清空之前的系统列表，因此程序先保留快照。
